# Capabilities: What SLATE Can Do

Generated by `node tools/capabilities.mjs --write` from `docs/capabilities.json`; `--check` holds it to the code. What SLATE can do, one capability a row, each held to the code by tools/capabilities.mjs: every command, look, route and file it names must exist, and every command a player issues must be named by a live row. Status is one of Missing, Partial, Implemented, Verified, Blocked, Retired. Verified means a test the gate runs (tests/**/*.test.ts) drives every command the row names through the engine (sim.execute, or run as a screen issues it) and checks the outcome and the readers the row claims, the standard docs/GAMEPLAY-COVERAGE.md holds a verified row to. A test that sets the change or a reader’s input by hand, calls a function in place of the command, or calls a reader the clock calls on its own (the day’s draw, the idle check, the month’s end) in the clock’s place or with its draw given, checks less: where a claimed outcome or reader is checked only that way, or not at all, the row isn’t Verified, or its claim is narrowed to what’s tested, and limits says which. A precondition set by hand (wages typed in, a document put in), a purchase made through the engine’s own spend, and a reader’s figure read by calling it after the command are setup, where the command and what reads it still run through the engine, and limits says so. Until a fourth review on 2026-10-12 this said any function called directly checked less, while docs/GAMEPLAY-COVERAGE.md counted those last two as setup, so a row could pass one standard and owe a note under the other. A check in the app or a tool outside the gate (manual, tools/acceptance-ui.mjs) can support a row and can’t make it Verified. Implemented means code exists for all of it and no such test checks one or more of its outcomes or claimed readers, which limits names, its verified layer Partial, or Missing where nothing in the gate checks it at all. Partial means the capability can’t be fully reached in a New Haven student’s life, and limits says why; a command out of reach and tested only on a life set up elsewhere is said so, as docs/GAMEPLAY-COVERAGE.md calls such a command unresolved. A command a New Haven life reaches, tested on a life no new one lives (a New Yorker’s, a Londoner’s), can still be Verified, and limits says on what life. The four layers are kept apart: a field in the model (schema) is not content, content is not a working interaction, and an interaction is not verified behavior.
